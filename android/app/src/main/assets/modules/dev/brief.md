- To build Android apps: javac/java/keytool (Alpine's JDK 17), aapt2, d8, apksigner and android.jar (API 35, under $ANDROID_HOME) are installed; if one goes missing, run android-sdk-install. Build with javac -> d8 -> aapt2 link -> add classes.dex to the APK with zip -> apksigner. Google's SDK/NDK and Gradle-based Android builds can't run here (they need x86-64 tools). Termux's ecj doesn't work here (it needs dalvikvm); use javac.
- To take an APK apart: apktool d <apk> (smali + resources), jadx <apk> (Java source). baksmali <apk> [out] and smali <dir> [out.apk] are shims onto apktool. If those are missing, run apk-tools-install.
- Termux/Android binaries DO run here: the device's bionic libraries are copied into the sandbox, and termux-install runs android-bootstrap, which rewrites each binary's interpreter and rpath to use them. If an Android binary ever reports 'not found' for its loader or a library, run: android-bootstrap. Those binaries land in /data/data/com.termux/files/usr and are already on PATH. Cross-compilers: termux-install clang binutils make cmake.
- To install an APK you built: if rish is available (Phone Use is on), install it yourself, telling the user first: rish -c "pm install -S $(wc -c < app.apk)" < app.apk (pm reads it from stdin, so no /sdcard needed). Android may show the user a confirmation. Otherwise copy it to /sdcard/Download and tell the user to open it from there.
